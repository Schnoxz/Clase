Gestión de Usuarios

La seguridad en una base de datos pasa por controlar quién puede conectarse y qué puede hacer. MySQL tiene su propio sistema de usuarios y privilegios: primero creas el usuario, luego le asignas permisos.

📌 Idea clave Un usuario en MySQL se identifica por dos cosas: nombre y host (desde dónde se conecta). 'usuario'@'localhost' es diferente de 'usuario'@'%'. El % significa "desde cualquier host".

1.1 — Creación de usuarios

Se usa CREATE USER seguido de las credenciales:

SQL — Crear usuario
CREATE USER 'nombre_usuario'@'localhost' IDENTIFIED BY 'contraseña_usuario';

Si quieres que el usuario pueda conectarse desde cualquier máquina, cambia 'localhost' por '%':

SQL — Usuario desde cualquier host
CREATE USER 'nombre_usuario'@'%' IDENTIFIED BY 'contraseña_usuario';

1.2 — Borrado de usuarios

Con DROP USER eliminamos un usuario por completo:

SQL — Eliminar usuario
DROP USER 'nombre_usuario'@'localhost';
⚠️ Atención Al borrar un usuario también se eliminan sus privilegios. Asegúrate de que realmente quieres hacerlo.

1.3 — Asignación de privilegios (GRANT)

Crear un usuario no le da acceso a nada. Los permisos se otorgan con GRANT. Puedes dar todos los privilegios sobre una base de datos:

SQL — Todos los privilegios sobre una base de datos
GRANT ALL PRIVILEGES ON nombre_base_datos.* TO 'nombre_usuario'@'localhost';

O bien permisos específicos sobre una tabla concreta:

SQL — Permisos SELECT e INSERT sobre una tabla
GRANT SELECT, INSERT ON empresa.clientes TO 'nombre_usuario'@'localhost';
Privilegio¿Qué permite?
ALL PRIVILEGESTodo (SELECT, INSERT, UPDATE, DELETE, CREATE, DROP…)
SELECTLeer filas de una tabla
INSERTInsertar nuevas filas
UPDATEModificar filas existentes
DELETEEliminar filas
CREATECrear tablas o bases de datos

✅ Principio de mínimo privilegio Asigna solo los permisos que el usuario realmente necesita. No uses ALL PRIVILEGES a la ligera.

1.4 — Eliminación de permisos (REVOKE)

Lo contrario de GRANT. Con REVOKE retiras un privilegio concreto:

SQL — Quitar el permiso INSERT
REVOKE INSERT ON empresa.clientes FROM 'nombre_usuario'@'localhost';
💡 Nota La sintaxis es casi igual que GRANT pero cambia TO por FROM. Fácil de recordar.

1.5 — Consultar usuarios de la base de datos

Los usuarios están almacenados en la tabla del sistema mysql.user. Puedes consultarla directamente:

SQL — Ver todos los usuarios y sus permisos
SELECT
    user AS UserName,
    host AS Host,
    db AS DatabaseName,
    Select_priv,
    Insert_priv,
    Update_priv,
    Delete_priv,
    Create_priv,
    Alter_priv
FROM mysql.user;

1.6 — Mostrar privilegios de un usuario concreto

Forma más directa y limpia de ver los privilegios de un usuario específico:

SQL — Ver privilegios de un usuario
SHOW GRANTS FOR 'nombre_usuario'@'localhost';

🧠 Resumen del punto 1 — Chuleta rápida

  • Crear usuario: CREATE USER 'u'@'host' IDENTIFIED BY 'pass';
  • Borrar usuario: DROP USER 'u'@'host';
  • Dar permisos: GRANT privilegios ON db.tabla TO 'u'@'host';
  • Quitar permisos: REVOKE privilegios ON db.tabla FROM 'u'@'host';
  • Ver permisos: SHOW GRANTS FOR 'u'@'host';
  • localhost = solo local · % = cualquier host
02

Transacciones

Una transacción es un conjunto de operaciones SQL que se tratan como una sola unidad. O se ejecutan todas con éxito, o no se ejecuta ninguna. Esto garantiza la integridad de los datos.

🔑 Propiedad ACID (lo que garantizan las transacciones) Las transacciones son Atómicas (todo o nada), Consistentes (dejan la BD en estado válido), Aisladas (no interfieren entre sí) y Durables (los cambios confirmados son permanentes).

El ejemplo clásico: una transferencia bancaria. Hay que restar de una cuenta y sumar en otra. Si la suma falla, la resta no debe haberse producido. Sin transacciones, los datos quedarían corruptos.

Ciclo de vida de una transacción:

inicio
START TRANSACTION
→
operaciones
SQL 1, SQL 2…
→
¿éxito?
Verificación
→
✓ COMMIT — cambios permanentes
✗ ROLLBACK — deshacer todo

Ejemplo completo — Transferencia bancaria

Transferir 1000€ de la cuenta 932656 a la cuenta 102656:

SQL — Transacción bancaria completa
-- 1. Iniciar la transacción
START TRANSACTION;

-- 2. Restar de la cuenta de origen
UPDATE Cuentas SET balance = balance - 1000
WHERE numeroCuenta = '932656';

-- 3. Sumar en la cuenta de destino
UPDATE Cuentas SET balance = balance + 1000
WHERE numeroCuenta = '102656';

-- 4. Si todo OK → confirmar los cambios
COMMIT;

-- 4. Si algo falla → deshacer todo
-- ROLLBACK;
🚫 Las sentencias DDL no se pueden revertir CREATE TABLE, DROP TABLE, ALTER TABLE… son sentencias DDL y hacen un COMMIT implícito automáticamente. No puedes hacer ROLLBACK después de ellas.

2.1 — Instrucciones de control en MySQL

Estas son las cuatro herramientas principales para manejar transacciones en MySQL:

ComandoFunción
START TRANSACTION o BEGIN Inicia una nueva transacción explícita. A partir de aquí los cambios no son permanentes hasta el COMMIT.
COMMIT Confirma todos los cambios de la transacción y los hace permanentes en la base de datos.
ROLLBACK Deshace todos los cambios realizados desde el START TRANSACTION. Como si no hubieran ocurrido.
SET autocommit Activa o desactiva el modo de confirmación automática para la sesión actual.

Para desactivar/activar el autocommit:

SQL — Autocommit
SET autocommit = 0;   -- desactiva el autocommit (control manual)
SET autocommit = 1;   -- activa el autocommit (comportamiento por defecto)
⚙️ Autocommit en MySQL Por defecto, MySQL tiene el autocommit activado. Esto significa que cada sentencia SQL es su propia transacción automática y se confirma inmediatamente. Para usar transacciones manuales, debes usar START TRANSACTION (que suspende el autocommit temporalmente) o hacer SET autocommit = 0.

Ejemplo práctico con control de errores (patrón habitual en un examen):

SQL — Patrón transacción con control manual
START TRANSACTION;

INSERT INTO pedidos (id_cliente, producto, cantidad)
VALUES (1, 'Laptop', 2);

UPDATE stock SET unidades = unidades - 2
WHERE producto = 'Laptop';

-- Si todo ha ido bien:
COMMIT;

-- Si ha habido algún error:
-- ROLLBACK;

🧠 Resumen del punto 2 — Lo que debes tener claro

  • Una transacción agrupa varias sentencias en una unidad atómica (todo o nada).
  • START TRANSACTION abre la transacción.
  • COMMIT confirma y hace permanentes los cambios.
  • ROLLBACK deshace todos los cambios de la transacción.
  • MySQL tiene autocommit = 1 por defecto → cada sentencia se confirma sola.
  • Las sentencias DDL (CREATE, DROP, ALTER) hacen COMMIT implícito y no se pueden revertir.
  • SET autocommit = 0 para control manual sin START TRANSACTION.
